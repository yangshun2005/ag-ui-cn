# 已弃用

SDK 仍为使用 1.0 之前协议的通信方保留的兼容层。每条记录说明被弃用的内容、替代方案、兼容层所在位置，以及兼容层本身的过期时间。以下所有兼容层均随 1.0 发布（2026-09-17），所有日期均为该发布日期起十二个月，而非各兼容层编写时间起算。过期日期之后，兼容层可能在下一个版本中移除，被弃用的结构将完全失效。

规范 1.0 契约（spec/1.0/schema.json）不包含这些结构。兼容性转换位于 TypeScript 客户端边界和中间件层：常驻边界（`CompatibilityBoundary`）在传输运行前升级传入内容，并转换出站请求中的旧版二进制附件。当对端上限等于或低于某版本时，会插入三个版本门控中间件。它们的作用方向并不一致。`BackwardCompatibility_0_0_39` 在出站时重写 `RunAgentInput`；`_0_0_57` 双向处理，先净化输入，再过滤并重写流（丢弃 `SUBAGENT_*` 事件，并从幸存事件中剥离 `subagentRunId`——包括 `MESSAGES_SNAPSHOT` 消息、`RUN_STARTED.input` 消息、`RUN_FINISHED` 中断结果）；`_0_0_45` 完全不触碰输入——它映射返回的事件流，将旧对端发回的 `THINKING_*` 结构转换为 `REASONING_*`。所有入站转换都会发出警告；出站时，仅当转换丢失或搁置内容时才发出警告（面向现代对端的无损二进制升级不发出警告）。`SUPPRESS_TRANSFORMATION_WARNINGS=true` 仅静默警告，不停止转换。

`BackwardCompatibility_0_0_47` 类及公开导出已移除。其二进制转换现在无论对端上限如何，均在 `CompatibilityBoundary` 中运行。请移除对该旧类的显式导入和注册。当消息同时包含现代附件及其旧版二进制镜像时，边界保留现代部分及其元数据。仅当旧版镜像的媒体类型、来源类型、MIME 类型及载荷或 URL 均匹配时才移除；任何旧版文件名也必须被现代部分保留。重复的现代附件和仅旧版附件保持为独立条目。

上述表中的可选 null 转换将每个整体可选 `null` 视为缺失字段，每次运行每个字段警告一次。它们在入站事件校验前运行，包括嵌套消息和 `RUN_STARTED.input`，覆盖内存运行、重连、SSE 和 protobuf。校验器还将事件级 `subagentRunId: null` 视为缺失，适用于直接向其传递事件的生产者。直接请求解析不经过此事件边界。接受旧输入的请求处理器必须在严格校验前本地省略所列可选 null；CopilotKit 的共享运行/连接解析器是此显式例外。转换辅助函数仍为 AG-UI 内部使用，无公开请求规范化 API。规范 Schema 仍拒绝这些整体可选 null，生产者序列化器会省略它们。现有的 `RunAgentInput.state: null` 解析器容忍行为继续产生 `undefined`。

这是一份选择性兼容列表：事件或消息的 `metadata: null` 已无法通过校验，仍属无效，所有未列出的可选 null 同样无效。必需的 JSON 载荷如 `CUSTOM.value: null` 仍然有效。

**元数据键下的 `null` 值**不在此列表，也永远不会列入：元数据按键开放，其中的 null 值是数据。只有替代整个可选字段的 `null` 才属于偏差。
